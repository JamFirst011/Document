# 存储器概述

**存储器的分类**：
1. 按照作用(层次):
    - 主存
    - 辅存/外存
    - Cache
2. 按照存储介质分为：磁表面，磁芯，半导体
3. 按照存取方式分为：
    - 随机存储器RAM：任何一个存储单元都可以随机存取，存取时间和物理位置无关
    - 只读存储器ROM：只能随机读出，但是不能写入(有些可以，例如SSD)
    - 串行访问存储器：需要按照物理位置先后进行寻址，包括
        1. 顺序存取存储器：只能按照某种顺序存取
        2. 直接存取存储器：介于RAM和顺序存取存储器之间，先随机查找到某个区域，例如寻道，然后在道内顺序存取
4. 按照信息的可保存型：断电后消息消失为易失性存储器，否则为非易失性存储器

## 性能指标

1. 容量
2. 单位成本：总成本/总容量
3. 存储速度：数据传输速率为数据的宽度/存取周期
    - 存取时间：从开始存取到结束的时间
    - 存取周期：进行一次读写的全部时间，包含例如对命令的转换，对地址的转换等；是进行两次独立访问存储器操作之间的最短间隔
    - 主存带宽：数据传输速率

**注意**：存取周期大于存取时间；

## 多层的存储系统

上一层的存储器作为下一层的高速缓冲，从而解决速度，容量，成本三者之间的矛盾；主存和cache之间的数据调动对程序员完全透明，主存和辅存之间的调动对应用程序猿透明

# 主存储器

## SRAM 和 DRAM

半导体存储器分为RAM和ROM，RAM又分为静态和动态；cache又SRAM实现，主存由DRAM实现；
1. **SRAM**：使用六晶体管MOS来记忆信息，信息被读出后不需要再生
2. **DRAM**：用电容来存储信息，存储密度更高，并且读出后内容就没了，需要定时刷新以及读后再生；

DRAM的信息只能维持1-2ms，相邻两次开始刷新的间隔称为刷新周期；常用的刷新方式有三种：注意刷新以行为单位
1. 集中刷新：在刷新周期内选取一个固定时间进行刷新，这段时间无法访存，称为死时间
2. 分散刷新：将工作周期分为两部分，后一部分用来刷新，赠长了存取时间，但是没有死时间，相当于死时间透明
3. 异步刷新：结合前两种方法，先用刷新周期除以刷新的行数得到每行最多需要的时间t，然后每t秒刷新以行，相当于分散了死时间

**DRAM的地址引脚复用技术**：存储器就像一个矩阵，每个点都是一个存储单元，可能存储着1B数据；如果行数为r，列数为c，那么应当使得他俩尽可能相等，然后只用行地址引脚，通过两次分别输入行地址和列地址；
1. **行缓冲器**：存储读出的一行数据
2. **突发传输**：给出一个地址后，可以传送连续多个存储单元的数据，即可以传送以行

**SDRAM**：同步的DRAM，一般的DRAM用异步方式访问，CPU在将信号传送给DRAM后，不断询问是否完成，无法做其他事情；但是SDRAM在时钟控制下进行操作，也就是SDRAM和CPU的时钟完全同步，因此CPU可以按照时钟周期预测主存的行动，因此可以支持流水线等操作，提高访存速度

## 只读存储器

特点：
1. 结构简单，位密度更高
2. 非易失性

类型：
1. MROM掩模式只读存储器：制造商直接写入，然后无法更改
2. 一次可编程只读存储器：用户可以自己写入，但是不能更改
3. 可擦除可编程EPROM：可以多次改写，但是写速度很慢
4. Flash：兼具ROM和RAM的优点，非易失性，并且可以较快的读写
5. SSD固态硬盘：和Flash同样

## 多模块存储器

空间并行技术，利用多个芯片来提高吞吐率

1. 单体多字：对芯片进行纵向的扩展，使得一个地址存储更多的字来提高吞吐率
2. 多体并行存储器：
    - 高位交叉编址：高位表示片号，低位为片内地址；当访问连续数据时，总是在一个片内一直访问，没有提高吞吐率
    - 低位交叉编址：低位表示片号，有m个片，每个片按摸m交叉编址；有两种启动方式：
        - 轮流启动：此时缓冲区/数据总线位数大小为一个存储单元，只能轮流启动，以流水线方式工作，此时设存取周期(从一个片上读出数据的时间)和总线周期(将数据从缓冲期传走)的比值为n，那么m必须大于等于n才能让所有片无等待的工作；此时读取一段连续数据，第一个数据需要一个存取周期，后面的都只要一个总线周期，提高吞吐率；
        - 同时启动：如果数据总线位数等于m*存储单元大小，那么所有片可以同时启动并行读取一段数据

## 注意

1. 存取周期不包含总线周期; 他的意义是存储器准备数据并产生数据的实践; 存储周期和存取周期定义一致; 所以存取周期=存储周期；因此，假设存取周期为c，总线周期为z：
    - 顺序编址：存取n快数据需要nc时间
    - 交叉编址：在流水线可以持续工作的前提下，需要c+(n-1)z时间
2. 判断一个n体交叉存储器存取过程中哪些访问可能发生体冲突时，默认使用同时启动，每n个为一组；如果在哪个地址发生了体冲突，那么后面的访问要延迟到下一个存取周期；具体见如下题目：答案为(17,9),(37,17),(13,37),(8,4)

1. 如果一个4B的数据在存储时没有对齐，例如4体交叉存储时，数据从2号芯片开始，那么需要两个周期才能将它读出；而如果他对齐了，也就是从0开始，那么一个周期就可以读取出
1. 分散刷新不存在死时间
2. DRAM一次完整的刷新需要占用一个存取周期(指刷新一行,一行指的是整个存储器的一行，而不是一个存储芯片的一行)，读出后写入(因为这里的读取/写入完全由硬件实现，不需要两个指令)

## 片选

片选信号的产生分为线选法和译码片选法：
1. 线选法：有多少个片就有多少位片选位，全都为1，哪位为0就表示选中哪个片
2. 译码片选法：用二进制数产生片选信号

**注意**：
1. 片选信号那几位不一定是最高位，因为地址线位数可能多于存储器的实际位数，因此可能是次高位，此时最高位没用；主存空间的逻辑地址大小决定了地址线/MAR的位数

# 外部存储器

## 磁盘存储器

1. 组成：
    - 盘片
    - 磁盘驱动器：驱动磁盘转动并通过磁头读写
    - 磁盘控制器：磁盘驱动和主机的接口，接受并解释CPU的命令
2. 存储区域：盘面，柱面，扇区
3. 磁盘高速缓冲：内存中的区域，用来存储将要被送到磁盘上的数据等
4. 磁盘的性能指标：
    - 记录密度：二进制数据量
    - 容量：非格式化容量是盘片表面可用的单元总数，格式化容量是格式化以后，例如增加扇区之间的间隙后，可用的单元总数，小于非格式化容量
    - 存取时间：寻道 + 旋转等待 + 数据传输
    - 数据传输速率：转速乘每条磁道的容量
    - 磁盘地址：柱面号 + 盘面号 + 扇区号

### 磁盘阵列

RAID，将多个物理盘组成一个逻辑盘，可以通过同时使用多个磁盘提高传输速率；通过镜像提高安全可靠性；通过数据校验提供容错能力

## 固态硬盘

1. 特性：由闪存组成，和U盘没有区别；由闪存翻译层(负责翻译控制信号，和磁盘控制器类似)，和闪存芯片组成，芯片内部被分为多个快，每个快被分为多个页，读取以页为单位，擦除以快为单位；相比于传统机械硬盘，速度更快；在向页写数据时，如果快内已经有数据，那么需要擦出整个快，并将快内所有内容复制到一个新快中
2. 磨损均衡：避免连续多次写入一个快，导致擦除次数过多损坏，有两种方式：
    - 动态：在写入的时候优先选择新快
    - 静态：更高级，不只是在写入的时候，自动检测新旧，让老快多负责读取为主的存储任务；

# 高速缓冲存储器

Cache主要利用程序的时间局部性和空间局部性；

## Cache的基本工作原理

Cache中存储主存快，保存主存中快的副本；当CPU要读取数据时，首先查询Cache，如果命中就不需要访问主存；如果没有命中仍然需要访存，并将数据掉入Cache，如果这时候cache满了，还需要换出某快，这个过程全部由硬件实现；**注意**：CPU和Cache以字为单位交换数据，缓冲和内存按快为单位交换数据；

要实现这个功能，要考虑一下问题：
1. 地址映射：内存空间到Cache空间的地址映射
2. 数据查找：如何在cache中查找数据
3. 替换策略
4. 写回策略

## 映射方式

1. Cache每一行都存储数据以及一些标记，标记包含：
    - 标记位：用于判断是否是需要的快，一般是快地址高位
    - 有效位
    - 脏位
    - 替换算法需要的位

下面三种映射方式中，行号/组号为cache索引

### 直接映射

主存中每一个快都对应唯一的一行，每一个地址除去低位的快内偏移，前面的号的mod r(cache共有r行)就是他对应的cache行号；当快对应的行已经有内容时发生冲突，要将新快掉入，不需要替换算法，利用率最低，命中率最低；

直接映射时，内存地址的结构为：标记 ｜ Cache行号 ｜ 快内偏移量

### 全相连映射

每一个内存快都对应所有的Cache行，此时利用率和命中率最高，但是标记位数很长，标记比较的时间更多，成本更高；此时内存地址结构为：标记 ｜ 快内偏移量，每一行一般都要设置一个比较器

### 组相连映射

综合直接映射和全相连，首先将Cache行分组，每组都对应直接映射的一行，在组内采用全相连；当组数等于行数时为直接映射；对于r路组相连(每组有r行)，需要设置r个比较器，地址结构为： 标记 ｜ 组号 ｜ 快内偏移；

**总结**：
1. 直接映射命中率最低，全相连命中率最高
2. 直接映射的判断开销最小，判断时间最短，全相连则最长
3. 直接映射标记所占额外空间开销最少，全相连最多

## 主存快的替换算法

1. RAND随机算法
2. FIFO算法
3. LRU算法：为每行设置一个计数器，表示该行的index；按照如下规则变化：
    - 当掉入新行时，他的index为0，所有行index加一
    - 当访问到某行时，他的index设为0，所有index小于他的行的index加一
    - 需要替换时，将index最大的行替换出去
4. LFU最常访问：计数器表示访问次数，当要替换时，一段时间内被访问次数最少的行被替换出去

## Cache的一致性问题

Cache写操作命中时有两种处理方法：
1. 全写/直写：当写命中时，写Cache中的数据，并立即将数据写回内存，当这个快被替换时就不需要写了，实现简单，但是访存数量过多，一般用写缓冲解决频率过高的访存
2. 回写法：当写命中时只写Cache中数据，并将脏位设置为1，当要将数据替换时在将数据写回到内存中；

写操作不命中时也有两种处理方法：
1. 写分配法：更新主存单元并将该数据掉入Cache中，每次写不命中都要从主存读一个块到Cache中; 一般和回写法一起用
2. 非写分配法：只是更新主存单元；一般和全写法一起用

**注意**：
1. Cache的标记阵列表示所有的标记，每一行都一个对应一个标记项，每个标记项中有有效位，标记等信息
2. Cache有效位的意义是表明cache行中的信息是否有效(屁话)
3. 在计算访问cache的缺失率时，注意他是如何访问数组的，总的访问次数要看对数组做了什么操作，例如a[i]=a[i]+1，那么总的访问次数就是数组元素个数乘2
4. 平均的访问时间由：cache缺失率，缺失/命中时的消耗的时钟周期决定，但是注意，缺失时访问的时钟周期数为cache访问时间+访问缺失的惩罚时间(包括读取内存和读取cache来将数据加入cache的时间)

# 虚拟存储器

## 基本概念

将主存和辅存统一编址，用户使用虚拟地址在这个巨大的地址空间中编程，在CPU执行时，将虚拟地址转化为对应的物理地址后，查看对应数据是否装入内存，如果装入就直接用物理地址访问，否则发生缺页异常，将数据从辅存中掉入内存；因为缺页的代价很高，因此辅存和主存之间采用全相连映射(虚拟页面到页框的映射)以及回写法

## 页式虚拟存储器

使用页表，每个进程都有一个页表，页表项包含：有效位，脏位，引用位(引用次数，用于实现页面替换算法)，以及页面所处页框的物理地址；
1. **优点**：页面长度固定，掉入方便
2. **问题**：数据不可能是整页，会有空间浪费

### 地址转换

虚拟地址结构为：高位为虚拟页号，低位为业内偏移，根据每个进程专属的页面Base寄存器找到页表，根据虚拟页号找到页表项，随后考察有效位；并将物理页号和页内偏移地址拼接形成物理地址

### TLB

页表为慢表，TLB为快表，类似Cache；保存页表的一部分副本，每一项包含页表项和标记，使用全相连时标记就是虚拟页号；使用组相连时，标记为虚拟页号的高位，中间是组号；

当同时配置Cache和TLB时，访存过程如下：
1. 虚拟地址转换
    1. 首先根据虚拟地址查TLB
    2. 若没有在查慢表
    3. 还是没有就引发异常，使用中断服务例程将页面掉入到内存中
2. 访存：
    1. 根据物理地址查询Cache
    2. 如果没有就查询主存

根据页面，TLB和Cache的关系，可以总结如下的缺失关系：

| TLB | Page | Cache |
| ---- | ---- | ---- | 
| T | T | T |
| T | T | F |
| F | T | T |
| F | T | F |
| F | F | F |

**注意**：
1. 最坏情况为最后一种，此时至少访问两次主存和一次硬盘
2. Cache缺失由硬件完成，缺页异常由软件解决，而TLB缺失既可以软件也可以硬件
3. 查找表时，可以快表和慢表同时进行

## 段式虚拟存储器

程序猿自己划分程序的段；此时段表项不仅包含段在内存中的地址，还需要包含段长度；
1. **优点**：具有逻辑独立性，便于编译和管理
2. **问题**：长度可变，分布空间不便

## 段页式

首先可以对程序进行逻辑分段，但是每段都必须在分成页；此时虚拟地址结构为：段号，页号，页内偏移；每个段都对应一个页表，访存时，首先根据虚拟段号找到段表项，根据段表项找到对应的页表基址，随后再用页号查页表得到物理地址；结合了页式和段式的优点，但是需要查两次表；

## Cache vs 虚拟存储

**相同**：
1. 提高系统性能
2. 把数据分为小块
3. 都有地址映射，替换算法，更新策略等问题

**不同**：
1. Cache解决系统速度，但是虚拟存储器解决主存容量问题
2. Cache纯硬件实现，但是虚拟存储器由OS和硬件共同实现

**注意**：
1. 虚拟存储系统也是依赖程序的局部性，因此要虚拟存储器发挥预期作用，运行的程序应该有较好的局部性
2. 虚拟存储系统对系统程序猿不透明(TLB缺失可以由软件解决)
