# 编码

主要有哪些规范，如何达成这些规范，如何开发单元测试样例，以及度量代码复杂度
  
1. 编码的规范需要做到:1.设计易读的代码:布局格式规范，命名规范，注释规范
2. 设计易维护的代码:将软件分为小的任务，提高其内聚性;并进行封装/ 可以通过定义新的 bool 变量来简化复杂决策，或者用新名字来封装复杂决策/变量起名规范，一个变量用于一个目的，不
    用全局变量，明确模块间模糊的依赖关系，通过写注释;
3. 设计可靠代码:契约式设计:如果一个函数在满足前置条件的情况下开始执行，在满足后置条件
    的情况下结束，那么就是可靠的
a. 异常方式:开始时检查前置，不满足就抛出异常，结束时做同样处理
b. 断言方式:用 assert 来检查前置和后置
c. 防御式编程:核心思想为在函数和外界交互时，在外界条件发生错误时，保证内部不受损害。
其实就是检查所有的输入和前置条件，比如输入参数，调用别的函数的返回值等但是他完全
      不会检验后置条件和输出，这些留给方法的调用者来检查
4. 使用模型辅助设计复杂代码:决策表，为代码，流程图。
5. 为代码开发单元测试用例:为方法开发测试用例;使用 Mock Object 为类方法开发测试用例(其
实就是某个类方法的流程调用了别的类方法，那么就用这个 Mock 来创立一个桩程序)，为类开发
测试用例。
6. 代码复杂度度量:有几种方法可以用来度量代码的复杂度:圈复杂度:为代码建立程序流程图，
那么该代码的复杂度为边数-节点数+2;直接计算程序中决策点的数量作为复杂度:即 if，for 等 决策点，这个决策点自我理解其实就是流程图中的岔路，还有一种方法用来度量类的复杂度:即 该类所有方法的代码复杂度的和
