# 数据库完整性

**完整性**包括数据的正确性和相容性：
- 正确性：数据符合现实世界语义，例如性别只能为男或女
- 相容性：相同对象在不同表中的数据是符合逻辑的，例如学生选择的课程必须是存在的课程

为了实现完整性，DBMS需要提供如下功能：
1. 提供定义完整性的机制
2. 进行完整性检查，例如在insert，update等操作或事务提交后进行检查
3. 进行违约处理，选择不执行当前操作或cascade进行操作

## 实体完整性

**定义**： 用`primary key`进行定义，对于单属性，可以定义为列级约束条件/表级约束条件，多属性只能表级

**检查和违约处理**：在insert，update后进行检查，若主码为空或不唯一则拒绝执行操作；要检查就要全表扫描时间开销很大，因此对主码自动建立索引，加快完整性检查速度

## 参照完整性

**定义**： `foreign key(cno) references course(cno)`
- 可以通过在后面加 `on delete cascade`, `on update no action` 来定义违约处理方式

**检查和处理**：
- 当参照表外码被更改/插入时，若被参照表中没有相应的值，那么直接**拒绝执行**
- 当被参照表的外码被修改/删除时，导致参照表中的外码没有引用了，可以
    1. 拒绝执行no action
    2. cascade，即同样删除/更新参照表中的相应属性
    3. 将参照表中相应属性置为null

## 用户定义的完整性

用户可以定义两种完整性：
1. 属性上的完整性：当插入/更新时进行检查，违反则不执行
    - `not null`
    - `unique`
    - `check(sex in ('male','female))`: 通过check规定属性的域
2. 元组上的完整性，通过check定义，插入/更新元组时需要满足check中的条件，例如 `check(sex = 'female' or name not like 'Ms.%')`

## 完整性约束命名子句

可以在任意完整性约束定义语句前面加 `constraint <name>` 来为完整性约束起名，以此来删除完整性约束; 通过alter table来实现完整性约束的删除/增加，例如

> alter table student drop constraint C1;<br>
> alter table student add constraint C1 check(sno between...)

## 断言

断言可以提供更具一般性的约束，可以涉及多个表/和聚集操作的比较；任何对其中表的更改都会触发对断言的检查；例如：
> 限定每门课的选课人数不能超过60<br>
> create assertion <name> check( 60 > (select count(*) from student group by course_id))

## 触发器

触发器是定义在表上的由事件驱动的特殊过程；也叫做 **事件-条件-动作**，即在事件到来时(insert/update/delete)，若该事件满足某个条件，则执行某个动作；定义格式如下：
> create trigger <_name> <br>
> {before|after} <事件> on <_table_name> <br>
> referencing new|old row as <_variable> <br>
> for each {row|statement} <br>
> [when<条件>] <_action>

1. `before|after`: 表示动作在事件发生前/后执行；当事件将要发生时，先看是否满足条件，如果满足，并且before，那么先执行动作在执行事件；否则先执行事件再执行动作；
2. `row|statement`: 表示触发器为行级/语句级触发器，行级表示对每一行都会执行action，语句级则每次触发只会执行一次
3. 如果action执行失败，那么事件就会终止执行，任何对象不会发生变化

例如：
> 再修改/插入教授数据时，如果教授工资低于4000，则将其工资改为4000；**注意**这里用before，在插入/更新之前就修改，而不是插入/更新之后，速度更快
> create trigger Insert_Or_Update_sal <br>
> before insert or update on teacher <br>
> referencing new row as new_tuple <br>
> for each row <br>
> begin if(new_tuple.job = 'professor') and (new_tuple.sal<4000) then new_tuple.sal = 4000; end if; end;

**激活顺序**：按照before触发器，事件，after触发器的顺序进行激活；同种类中按照定义的顺序进行激活;
