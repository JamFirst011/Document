# IO接口

IO接口是主机和外设的交接界面；外设的工作方式和数据格式有很大差别，IO接口的设置就是为了消除这些差异

## IO接口的功能

1. **进行地址译码和设备选择**
2. **实现主机和外设之间的通信联络控制**：协调不同的工作速度
3. **实现数据缓冲**：其实也是为了消除速度差异，实现数据的异步传输
4. **信号格式的转换**
5. **传送控制命令和状态信息**

## 基本结构

IO接口通过IO总线和CPU链接，数据线连接数据缓冲/控制/状态寄存器，注意，读写等IO命令通过控制线传输，但是某些特殊指令可以通过数据线传输，还负责传输中断类型号；

控制线和地址线连接地址译码和IO控制逻辑；该控制逻辑对地址和指令进行译码，将命令进一步发送给外设；并且还可以收集外设状态并存储到状态寄存器中；

### IO接口的类型

1. 按照数据传输方式可以分为**并行接口**和**串行接口**
2. 按照主机访问IO设备的控制方式可以分为
    - 程序查询接口
    - 中断接口
    - DMA接口
3. 按功能灵活性可以分为**可编程接口**和**不可编程接口**

## IO端口及其编址

IO端口即IO接口中可以直接被CPU访问的寄存器；有如下编址方式：
1. **独立编址**：IO端口有不同于主存地址的专门地址，这个地址可以和主存地址重合；用专门的IO指令来表明访问的是IO地址空间；
    - 优点：IO端口数很少，因此地址码位数很少，译码简单，寻址速度快
    - 问题：需要专门设计IO指令，增大了控制的复杂性
2. **统一编址**：存储器映射方式，将一部分主存地址分给IO端口，他们分别放在不同的段中，使用访存命令访问IO端口，根据访存的位置就可以判断是不是访问的IO端口；
    - 优点：不需要专门IO指令，端口有很大的编址空间
    - 问题：占用部分主存地址，译码电路更加复杂

**注意**：
1. 因为状态/命令信息的传递完全是反向的，因此状态和控制端口可以合用一个寄存器

# IO方式

有如下IO控制方式

## 程序查询方式

CPU不断读取状态端口的状态，并根据状态决定下一步执行的步骤；流程如下：
1. 初始化参数
2. 发出命令，启动IO
3. IO设备准备数据，CPU不断查询状态字
4. 待准备就绪后，传送一次数据
5. 修改地址和计数器等参数
6. 回到3重复执行，直到传输结束(计数器为0)

根据3中查询的方式可以分为：
1. 独占查询：设备启动后一直持续查询，完全串行工作
2. 定时查询：如名，周期性查询接口状态

## 程序中断方式

**思想**：当程序需要IO时，发送IO命令启动外设，随后阻塞进程，此时IO准备数据，CPU运行其他进程，二者并行工作；当外设准备好数据后，发送中断，CPU响应中断并执行中断服务例程来传输数据；**注意**：如果缓存大小为n，外设准备n大小数据的时间小于中断之间，那么不能使用中断方式，因此中断传输数据还没传输好，下一个n个大小数据又准备好了，当前数据就会被刷新；

### 工作流程

1. **中断请求**：设置中断请求标记寄存器，每一位表示一个中断源，为1则表示该中断源发送了中断请求；
2. **中断响应判优**：中断有响应优先级和处理优先级，响应优先级是固定的，CPU按照响应优先级选择中断，如果在执行中断服务例程时不允许中断嵌套，那么处理优先级没用；否则，可以通过中断屏蔽字改变中断的处理优先级，从而改变中断请求被响应并处理的顺序；**注意**：不可屏蔽中断优先级永远大于可屏蔽中断
3. **响应中断的条件**：CPU在一条指令结束后响应中断
4. **中断响应过程**：直接由硬件实现，称为中断隐指令，也就是中断响应实际上就是在执行中断隐指令(不是具体指令，而是事务序列)，步骤如下：
    - 关中断
    - 保存断点：包括PC和PSW，保存的PC通常是下一条指令地址
    - 识别中断源，查找中断服务例程并将对应程序地址写入PC；
5. **中断向量法**：响应过程的第三步，识别中断源有中断向量和非中断向量(软件查询法)；根据中断源得到中断类型号，进而查中断向量表得到中断向量，即中断服务例程首地址
6. **中断处理过程**：首先是中断响应过程，随后执行中断服务程序，包括如下步骤
    - 保存现场和屏蔽字
    - 开中断
    - 执行中断服务程序
    - 关中断
    - 恢复现场和屏蔽字
    - 开中断
    - 中断返回

### 多重中断和中断屏蔽技术

在执行中断服务程序时可以转去处理新的中断，那么为多重中断/中断嵌套，否则为单重中断；

**中断处理优先级**为中断的实际处理次序，可以使用中断屏蔽字动态调整；如果不使用屏蔽字那么就和响应优先级一样；有中断屏蔽寄存器，每一位对应一个中断源，为1则表示处理中断时屏蔽来自该中断源的中断请求；每个中断源都有相应的中断屏蔽字，CPU在执行服务例程时会将中断屏蔽字送入中断屏蔽字寄存器中；当允许多重中断时，选择一个中断执行时，如果有新的中断请求，那么将他们中未被屏蔽的中断送入判优电路，选择**响应优先级**最高的中断进行响应；

中断屏蔽字只有CPU在运行中断服务程序时才有用；例如：有四个中断源，响应优先级从高到低为ABCD，若想将他们的优先级修改为ADCB，就将A的屏蔽字设置为1111，D设置为0111，C设置为0110，B设置为0100即可；当A执行结束后，会先选择B，但是在B中断服务一开始，就会立马切换到C，随后立马切换到D这样执行；

**注意**：
1. 中断方式也是由软件进行数据传输的，也就是在中断服务例程中进行数据的传输；

## DMA方式

完全由硬件进行成组数据传输；数据传输不经过CPU，适用于需要大量传输数据的设备；DMA中，中断的作用仅限于故障和正常传输结束时的处理

### 特点

1. 数据传输时，主存地址的确定，计数器的实现都有硬件电路直接实现
2. 主存中开设专用缓冲区来接受外设数据
3. 传送速度快，并行度高，提升了系统效率
4. 开始前通过程序进行预处理，结束后通过中断进行后处理

### DMA控制器的组成

对数据传输进行控制的硬件为DMA控制器/接口，外设连接DMA控制器，通过控制器向CPU提出DMA请求；功能如下：
1. 接受外设的DMA请求，并向CPU发出总线请求
2. CPU响应后发出总线响应信号，DMA接管总线
3. 确定传送数据的地址和长度，维护地址寄存器和计数器
4. 规定数据的传输方向，发出读写控制信号，进行数据传输
5. 向CPU报告传输结束

DMA控制器包含如下部分：
1. 主存地址计数器
2. 传送长度计数器
3. 数据缓冲
4. DMA请求触发器：用于标记设备的DMA请求
5. 控制/状态逻辑
6. 中断机构：用于提出中断请求

### DMA传送方式

如何解决DMA和CPU访问主存的冲突

1. **停止CPU访存**：直到DMA传送结束后CPU才能访存，因为DMA的优先级更高
2. **周期挪用**：DMA有数据传输时挪用一个存取周期，传输一个字后立马释放总线；但是每次挪用一个存取周期，就要重新申请，建立和归还总线控制权
3. **DMA和CPU交替访存**：CPU的工作周期分为两个部分，分别进行CPU和DMA的访存，适用于存取周期小于工作周期的情况；每次传输数据后不需要申请/释放总线，谁能访存通过时钟分时控制

**注意**：DMA传送时，每次DMA只能传一个快大小数据，随后就要重新申请总线

### DMA的传送过程

1. **预处理**：CPU设置一系列参数，包含传输方向，地址，大小等，随后继续工作；直到IO设备准备好数据后发送DMA请求，DMA控制器进而发送总线请求拿到总线控制权
2. **数据传输**：以数据快为单位进行数据传输
3. **后处理**：传输完后，DMA控制器发送中断请求，执行中断服务程序校验数据等；

## DMA和中断的区别

1. 中断方式需要切换进程
2. 对中断请求只能在执行周期最后，但是对DMA的响应可以发生在任意一个机器周期结束后；
3. DMA请求的优先级高于中断请求
4， 中断靠程序传输，DMA靠硬件传输

**注意**：
1. 中断向量地址是中断程序入口地址的地址
2. 用户程序需要IO时引发的中断是访管中断(即sys_call)
3. 中断响应周期中，由中断隐指令将中断触发器置0，而不是关中断指令
4. 设置中断屏蔽字可以改变中断服务例程执行完的顺序
5. 注意DMA时，由外部设备发起DMA请求
6. 中断IO不适合高速设备
