# 文件系统基础

**基本概念**：以硬盘为载体的存储在计算机硬盘上的信息集合；**文件系统**为用户提供管理，创建访问文件的需求

1. 在UNIX中，所有设备都被视为特殊文件，因为访问设备和访问文件的方式基本一样

## 文件的定义

**文件的组成**：
1. 存储的数据
2. 分类和索引信息
3. 访问权限的信息

有如下定义：
1. **数据项**：最低级的数据组织形式，有两种类型
    - 基本数据项：一个属性的一个值
    - 组合数据项：多个基本数据项
2. **记录**：数据项的集合，描述对象在某方面的属性
3. **文件**：相关元素的集合，可分为有结构：由若干记录组成；无结构：字符流

**文件的属性**：包括类型，名称，创建者，拥有者等

## 文件控制块和索引节点

**注意**：
1. 文件目录中存放的就是FCB，就算使用inode，里面存储的也是FCB，因此文件目录项一定不包括文件控制块的物理地址

**FCB**：是存储控制文件需要的各种信息的数据结构；和文件一一对应；FCB的集合为文件目录，也被视为一个文件称为目录文件；FCB主要包含如下信息：
1. 基本信息：文件名，存储位置等
2. 存取控制信息：存取权限等
3. 使用信息：建立时间，上次访问时间等

### 索引节点

当需要查找文件时，需要将文件目录一盘一盘装入到内存中，来一个一个查找，但是此时FCB中除了文件名臣都没有用；因此设定一个索引节点，称为i节点/inode，来存储除了文件名之外的所有元数据；这时在FCB中仅有两个字段，即文件名和inode编号/指针，可以在检索文件时大大减少磁盘IO的次数；Inode包含如下信息：
1. 文件主标识符
2. 文件类型
3. 存取权限
4. 物理地址：含有13个地址项，可以直接/间接的给出存储该文件数据的盘号
5. 文件长度
6. 链接计数：没懂
7. 存取时间<br>
找到目标文件后，需要将inode装入内存中，此时要添加如下信息：
1. inode号
2. 状态：inode是否上锁
3. 访问计数
4. 逻辑设备号：所属文件系统的逻辑设备号
5. 链接指针：没懂

## 文件的操作

基本操作有创建，删除，读写，如何打开和关闭呢，按照是否允许多个进程打开同一个文件分为两种：

### 打开文件表

操作系统在内存中维护一个打开文件表，每当进程调用系统调用open并输入文件名和存取权限后，操作系统按照上面的方法查找文件，并将FCB掉入内存，作为打开文件表的一个表项，并为进程返回该表项的索引：**文件描述符fd/文件句柄**；随后进程可以直接用这个索引来对调用系统调用，对文件进行其他操作；注意，此时因为只有一个打开文件表，每个文件只有一个读指针/写指针，因此不能多个进程同时读一个文件；

### 多个进程可以打开同一个文件

此时为每个进程再维护单独的打开文件表，在系统的打开文件表中维护和进程无关的信息例如文件地址，在单独打开文件表中维护读写指针等信息，以及系统打开文件表的索引；此时，打开文件时首先将FCB添加到系统的打开文件表，再在单独的打开文件表中添加一项；当另外一个进程打开同一个文件后，只需要在他的单独打开文件表中添加一项，并存储对应文件在系统打开文件表中的索引即可；在系统打开文件表中为每个文件维护一个打开计数，当计数为0时即可删除该表项以及内存中的PCB；

**注意**：当文件打开以后就只用fd来访问文件，而不需要在用文件名

## 文件的逻辑结构

逻辑结构即用户视角下文件的结构，文件内部数据是如何组织起来的；有如下结构：
1. 无结构文件/流式文件：字符流，读取文件时只能一个字符一个字符读取
2. 有结构文件：文件由记录组成(每个记录都有一个key)，分为
    - 定长记录：检索记录的速度更快
    - 变长记录

有结构文件按照记录的组织方式可以分为如下类型：

1. **顺序文件**：所有记录按照key的顺序(顺序结构)，或添加顺序进行排列(串结构)，顺序结构如果是定长记录，那么很好检索，如果是变长，那么不论怎么存储，顺序文件对单个文件的检索都十分耗时；但是对一批记录的操作效率是最高的
2. **索引文件**：为了解决变长记录顺序存储在检索上的耗时，在顺序文件的基础上维护一张索引表，每个表项对应一个记录，包括记录的长度和指针，并按照key进行排序，因此这个索引表可以看成一个顺序结构定长记录的顺序文件，可以很快速的对记录进行索引，但是需要额外的存储开销
3. **索引顺序文件**：对上面的综合，对顺序文件中记录分组，每组对应一个索引项，首先查找索引表，然后得到分组的指针后再在分组中顺序查找即可；注意此时查找索引表只能顺序检索而没法像索引文件一样随机检索(因为分组大小不一样，因此无法知道目标记录属于哪一组，只能一组一组查看)
4. **哈希文件**：维护一个哈希函数，输入key后可以直接得到物理地址，有很高的存取速度但是可能引起冲突

## 文件的物理结构

如何在物理存储设备上分配和组织文件，这里主要介绍如何为文件分配块(在物理存储设备上，存储空间也被分为块，每块大小和页一般一样)

1. **连续分配**：要求文件在磁盘上占有连续的块，支持顺序访问和直接访问，寻到时间短，但是缺点有：
    - 产生很多外部碎片
    - 必须事先知道文件长度，并且文件长度很难动态变化
2. **链接分配**：盘快不需要连续，因此消除了外部碎片，大小可以动态变化，有如下方式：
    - 隐式链接：FCB中存储第一个块号，每个块中都存储下一个块号，只能顺序访问，并且浪费块中的存储空间，并且如果一个指针出错那么整个文件都访问不到了
    - 显式链接：构建一张表，称为文件分配表FAT，存储在内存中，每个表项都对应一个块号，并存储了该块号所属文件的下一个块的块号，可以用特殊数字来表示文件的最后一个块或空闲块；因此可以用FAT对磁盘空闲空间进行管理；可以随机访问，并且显著减少了访问磁盘的次数，但是要占用很大的内存空间
3. **索引分配**：在打开某个文件时只需要将他对应的块号都读入内存即可，不需要整个文件系统所有快号的状态
    - 单级索引分配：文件中专门用一个块来顺序存储所有块的块号，并在FCB中记录这个索引块的地址；可以直接访问，但是增加了额外的存储空间；并且如果是大文件就要多个索引块，随机访问的效果就不好了
    - 多级索引分配：采用多级索引，一级索引块(主索引)记录所有二级索引块的块号，这样对大文件也可以快速的查找，但是如果是小文件，也需要进行多次磁盘访问，降低了对小文件访问的性能
    - 混合索引分配方式：融合了单级索引和多级索引，同时照顾到对小文件和大文件的访问；在UNIX中，在FCB中共有13个块地址，前10个直接指明文件块的地址(直接寻址)；后面三个块分别对应一级/二级/三级索引块地址；若块大小为4KB，每个索引项占4B，那么文件最大为4TB+4GB+4MB+40KB

**注意**：
1. 为文件添加快时需要的IO次数：读取块需要一次，如果改变了块，将块写回也需要一次；例如：
    - **连续分配**：在中间插入块，需要块的移动前面/后面的所有块，因此IO次数为移动块数✖️2+1
    - **连接分配**：读取前面的块，找到要插入前一个块，改变这个块的下一个块地址，并将它和新快写会，因此共要前面块数+2

## 文件保护

可以通过**口令，加密和访问控制**实现对文件的保护机制

**访问类型**：可以限定用户对文件的访问类型，例如读，写等

1. **访问控制**根据用户身份来限制用户对文件的访问类型，采用访问控制表ACL，规定每个用户及其允许的访问类型；控制表内容包含拥有者，组和其他用户的访问类型，在创建时在FCB中记录拥有者以及他所在的组；在访问文件时确定用户的类型后，就可以限制他对文件的访问类型；很方便
2. **口令**：在创建时设置口令，在访问时必须提供口令，口令直接存储在系统中不安全
3. **加密**：在创建时对文件加密，在访问时需要提供密钥，解密和加密需要额外时间开销

**注意**：只有访问控制能限制用户对文件的访问类型，剩下两种文件保护机制只能防止文件被别人窃取

# 目录

**注意**：
1. 当采用硬链接共享时，多个进程打开一个共享文件只需要一次inode的读取；因为在将inode读入到系统的打开文件表后，再次打开文件时会先查找打开文件表，查找到了就直接返回了；但是如果采用软链接，那么需要多次，因为软连接对应的inode和原文件的inode不一样，要访问到文件内容后才能知道原文件的位置；
2. 在访问文件时，根据文件名对目录进行检索，检索性能由如下因素决定：
    - 目录项数量
    - 目录项大小：决定了磁盘IO的数量
    - 目录项在目录中的位置

## 基本概念和操作

FCB的集合就是文件目录，目录需要实现以下特性：
1. 目录管理要按名存取
2. 目录检索速度要快
3. 提供访问控制
4. 允许不同用户对不同文件采用相同的名称

目录应该支持如下操作：搜索，创建，删除，创建，删除目录，移动目录，显示等

## 目录结构

有如下结构：
1. **单级目录结构**：只有一个目录表，每个目录项对应一个文件的FCB；查找速度慢，并且文件不能重名；
2. **两级目录结构**：文件目录分为主文件目录MFD和用户文件目录UFD，此时MFD记录所有UFD的名称和位置，而FCB则包含在UFD中；两级目录缺乏灵活性
3. **树型目录结构**：用路径来访问文件(也可以在设置当前/工作目录后用相对路径访问文件)，可以对文件进行分类，但是增加了磁盘访问速度，会影响查询速度；
4. **有向无环图结构**：在树形结构的基础上，允许多个父节点指向一个子节点，也就是多个目录可以同时包含同一个文件，来提供更好的文件共享；此时文件中要维护共享计数器，只有在计数器为0时才能删除他(实际上还是用两个同样的FCB指向同一个文件地址)

**注意**：
1. 若采用两级目录结构，那么检索一个文件平均要检索的目录项数为二级目录个数/2 + 二级目录中目录项个数/2

## 文件共享

有向无环图文件共享的问题是，要将被共享文件的物理地址复制到多个FCB中，如果一个进程改变了文件物理地址，那么另外一个用户无法及时感知到；因此有如下共享方式：
1. **硬链接**：采用inode，将物理地址等属性都放到inode中，此时多个FCB指向同一个inode，inode中记录共享文件的用户数量；访问速度很快
2. **软链接/符号链接**：当某用户要共享文件时，文件系统创建一个新的LINK类型文件，文件中存储了要共享文件的绝对路径；这样当该用户访问这个共享文件时，文件系统发现访问的是LINK类型文件，他知道这是一个符号链接，就会用其中的路径去查找真实的FCB；此时只有文件的拥有着才持有文件的inode指针，因此若拥有着删除文件，其他用户在进行访问时会访问到空指针，就会删除本地的LINK文件；但是要多次访问磁盘，LINK文件也要占更多磁盘空间

**注意**：
1. 软连接的引用计数没用，因此添加软链接不会给原文件增加引用计数，每个软链接文件本身的计数也是1；
2. 采用硬连接共享文件时，只要文件被多个文件共享就不能删除文件；但是使用软链接就可以随便删除文件；若有目录包含了被共享的文件，那么如果该文件不能被删除，那么目录也不能被删除；

# 文件系统

## 文件系统结构

文件系统为用户提供高效的磁盘访问，例如定位，存储和提取数据，层次结构c从上到下为：
1. 应用程序
2. 逻辑文件系统：提供统一的调用接口，抹除不同实际文件系统的差异
3. 文件组织模块：组织文件，将文的逻辑快转化为物理快，管理空闲空间
4. 基本文件系统：管理缓冲区，向特定的设备驱动程序发送通用命令
5. IO控制：包含设备驱动程序和中断处理程序

## 文件系统布局

**结构**：每个磁盘上都有很多分区，每个分区都可以挂载一个文件系统，一个文件系统至少包含一个分区；每个**磁盘**的第一个扇区都是都包含：
- 主引导记录MBR：确定活动分区，BIOS读入MRB后运行，来确定活动分区，并读入这个活动分区的第一快(该分区的引导块)，相当于从当前磁盘中选择一个文件系统
- 分区表：记录每个分区的地址

每个文件系统包含如下部分：
1. 引导块：包含程序，负责启动该分区的操作系统
2. 超级快：包含该文件系统的所有关键信息，首次启动时会被读入内存，包含分区快的数量，快大小，空闲快信息等
3. 空闲快信息：位示图，给出所有空闲快位置用于空间管理
4. Inode：存储所有文件的Inode
5. 根目录：存放目录树的root
6. 目录和文件：具体目录和文件

## 文件存储空间管理

包含文件系统的分区称为卷volume，卷中文件区和目录区(存储FCB)的空间分离；文件存储设备分为很多大小相同的物理快并以此为单位交换信息；对于存储空间有如下管理方式：
1. **空闲表法**：为所有空闲区域建立一张分区表，存储所有空闲连续分区的第一个空闲快号和长度；只能分配连续空间，采用first-fit之类的算法分配和回收都和内存的动态分配类似；优点是分配速度很快
2. **空闲链表法**：将所有空闲的盘快串成一个链表，有两种方式：
    - 空闲盘快链: 所有空闲盘快作为链表node，分配时从首开始取要求大小的盘快分配给用户，回收时将回收的盘快加到尾部；分配效率较低，盘快链很长，并且很难分配连续空间
    - 空闲盘区链: 简短了链表长度，感觉和空闲表法基本一样了；效率较高，但是分配和回收的过程比较复杂
3. **位示图**：用每一位表示一个盘快，连续分配和离散分配都很擅长；且位示图很小，问题是位示图大小会随磁盘大小改变，因此只适用于小型计算机
4. **成组链接法**：在内存中维护一个空闲盘块号栈，并对盘快分组，例如100个盘块为一组，栈中存储刚好一个组；栈底位置的盘快存储下一个组的信息，例如0-99组中，99号盘快就存储下一个组信息；分配时从栈顶开始，分配后就移动指针，空闲盘快数量减1，当指针指到栈底时，就读取下一个组的信息到栈中；回收时，将回收的盘快好压入栈中如果满了就将栈中所有盘快号存入一个新盘快，并将该盘快作为栈底；（其实我没懂这个）

## 虚拟文件系统

VFS屏蔽了不同文件系统的差异，为用户提供统一的操作接口；面向对象，定义四种对象类型，每个对象都包含数据和接口，如下：
1. 超级快对象：表示一个文件系统；存储元信息，提供分配inode等接口
2. inode对象：表示一个特定文件，包含inode数据，并提供创建新inode，创建硬链接等接口
3. 目录项对象：在磁盘上没有对应的数据结构，是路径的组成成分，包含指向对应文件inode的指针，父目录和子目录的指针；VFS在遍历路径时将她们逐个解析为目录项对象
4. 文件对象：已打开文件；包含目录项对象，文件系统等；

VFS存在于内存中，当要访问文件时，操作系统调用VFS提供的接口，VFS进而调用具体设备提供的接口来访问磁盘；因此文件系统的主要功能实际上就是按名查找文件；

## 文件系统挂载

mount，在使用前必须先挂载/安装文件系统；要将文件系统mount到特定目录上后才能进行使用，通过文件系统来访问设备上的文件

1. **Windows**：两级目录，根目录下有各个文件系统；
2. **UNIX**：使用系统的根文件系统，在启动时自动安装；其他文件系统需要挂载到根文件系统的目录后才能访问；
