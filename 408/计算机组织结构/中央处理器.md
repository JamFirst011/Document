# CPU的功能和基本结构

## CPU功能

由运算器和控制器构成，运算器负责执行运算，控制器负责产生CPU内的控制信号，以及控制计算机各个部分之间的数据流动，主要有如下功能：
1. 指令控制：指令的取，分析，执行
2. 操作控制：产生完成指令需要的控制信号
3. 时间控制：控制信号的出现/持续时间
4. 数据加工：对数据进行运算
5. 中断处理

## 基本结构

由运算器(数据通路)和控制器(控制部件)组成；

**运算器包含**：ALU，ACC，通用寄存器，程序状态字寄存器，移位寄存器

**控制器包含**：PC，IR，指令译码器，时序电路和为操作信号发生器；

### 寄存器

按照用户是否可见分为：
1. 用户可见：通用寄存器，状态字寄存器，PC
2. 用户不可见：不能对他们编程，一般被控制部件使用，MAR，MDR，IR，暂存寄存器，累加寄存器，移位寄存器

按照所属部分分类：
1. 运算器中：
    - 通用寄存器
    - 累加寄存器ACC：暂存ALU运算的结果
    - 移位寄存器
    - 暂存寄存器：用于存储从总线来的数据，在取出下一个操作数的同时将其送入ALU，因为单总线不能同时取两个数送给ALU
    - 状态字寄存器
2. 控制器中：
    - PC
    - IR

**注意**：
1. CPU中不包括地址译码器，他位于存储器中；
2. CPU的专用寄存器包括：PC，IR，MDR，MAR，PSW

# 指令执行过程

## 指令周期

**指令周期**：CPU取出并执行一条指令需要的全部时间；由如下周期构成，不同指令的周期不同
1. 取指周期
2. 间址周期：访问主存取出操作数地址
3. 执行周期: 取数，计算，存数
4. 在指令执行结束前发中断查询信号，如果有中断则进入中断周期

## 指令周期的数据流

数据流是根据指令要求依次访问的数据/设备序列，不同的指令的数据流也不同


1. 取值周期： 数据流为：PC - MAR - 地址总线 - 存储器 - CU发出命令 - 控制总线 - 存储器 - 数据总线 - MDR - IR - CU发出控制信号，PC+1
2. 间址周期：同理，从IR中获取地址，访问主存后，将操作数地址读取到MDR中
3. 执行周期：没有统一的数据流
4. 中断周期：改变SP，随后将断点保存到栈中，随后更改PC

## 指令执行方案

1. 单周期处理器：所有指令选用相同的执行时间(最长指令执行时间)，串行执行，CPI为1(平均时钟周期为1)
2. 多周期处理器：一个指令周期包含多个时钟周期，串行执行，需要几个时钟周期就分配几个时钟周期，CPI大于1
3. 流水线：CPI=1，并行

**注意**：
1. 只有在指令长度相同的情况下，取值操作才是相同的

# 数据通路的功能和基本结构

CPU由数据通路和控制部件组成；

**数据通路**：数据在指令执行过程中经过的路径以及部件为数据通路，例如ALU，寄存器等

## 数据通路的组成

1. **组合逻辑元件/操作元件**：输出仅取决于当前的输入，不含存储单元，用于操作，例如ALU等
2. **时许逻辑单元/状态元件**：用来存储，寄存器

## 数据通路的基本结构

由入下几种：
1. CPU内部单总线：将所有元件都连接到一条内部总线上；存在较多冲突现象，性能较低(单周期处理器不能用单总线，因为单总线一个时钟周期只能操作一次，不能执行完一个指令)
2. CPU内部多总线方式：多条总线，可以同时在多个总线上传输不同的数据，效率更高
3. 专用数据通路方式：不使用共享的总线，根据数据流动路径在元件之间安排专门线路，硬件量大

## 数据通路的操作

**注意**：任意时刻只能有一个元件向总线上传输数据；举例：加法指令的执行：
1. 因为ALU不带存储，所以必须首先将一个操作数送到一个暂存寄存器中
2. 随后将第二个操作数发送到总线上，并打开ALU的两个输入口，结果存到暂存寄存器中
3. 将结果读到通用寄存器中

共使用三个时钟周期

**注意**：
1. 一条指令执行过程中，单周期CPU的每个控制信号取值一直不变；但是多周期的控制信号可以发生变化；
2. 若有通用寄存器组，并且有rs/rd(表示读/写的寄存器编号)连接到寄存器组，那么rd连接到地址译码器，rs连接到多路选择器(选择器输入端连接所有寄存器，输出端连接总线)，并且rs/rd来自IR寄存器
3. 寄存器IR和PSW的输出端连接到CU的输入端
4. 在执行访存指令时，如果发生了缺页异常，那么这一次访存指令会访问两次TLB

# 控制器的功能和工作原理

控制器是计算机系统的指挥中心，主要功能有：
1. 从主存中取值，并指出下一条指令的地址
2. 译码，产生操作控制信号
3. 指挥并控制各个部件之间的数据流动(CPU，主存，输入/输出设备等)

分为如下两种控制器，他们的PC和IR相同，但是产生控制信号的方式不同

## 硬布线控制器

完全由复杂硬件实现，首先译码，将n位操作码转化为 $2^n$ 个输入，每条指令对应一个输入，随后根据该输入，状态字，以及时钟脉冲产生控制信号；速度很快，一般用于RISC架构，但是扩展性差，复杂

## 微程序控制器

包含一个控制存储器，里面存放了很多微程序；每条指令可以转化为一个微程序，微程序包含多条微指令；每个微指令对应多个微操作命令；
- **微命令**：控制部件发出的控制命令，控制序列的最小单位，相容命令即可以同时出现的
- **微操作**：部件收到命令后执行的操作
- **微指令**：若干微命令集合，包含：操作控制字段/操作码，顺序控制字段/地址码，指出下一条微指令的地址；
- **微周期**：取出并执行一条微指令的时间，通常为一个时钟周期
- **控制存储器**：用ROM实现

所以微程序实际上是对机器指令的解释，事先编制好放在控制存储器中；控制器中存放微指令地址和指令的寄存器分别为 $\mu PC,\mu IR$

### 组成和工作过程

组成包括：
1. 起始和转移地址形成部件：生成PC值
2. 微PC
3. 控制存储器
4. 微IR

工作过程包括：
1. 取指：将取指微程序的入口地址送入微PC并执行；
2. 通过机器指令的OP字段，通过起始和转移地址形成部件形成对应的微程序起始地址
3. 逐条取出微指令并运行
4. 回到第一步

控制存储器CM中的微程序个数为：指令种类加上取值，间址和中断等公共的微程序数

### 微指令的编码

如何对微指令控制字段进行编码，有如下方式：
1. 直接编码：每一位代表一个微命令，不用译码，简单，执行速度快
2. 字段直接编码：将OP分为多个字段，每个字段表示一组互斥微命令，不同字段之间互不影响；每个字段都要留出一个值表示不操作，因此一个表示四个命令的字段需要3位
3. 字段间接编码：一个字段的微命令需要由其他字段的微命令解释，进一步缩短微指令字长；

### 微指令地址的形成方式

由如下方式生成：
1. 由微指令的下地址字段直接给出
2. 根据机器指令操作码形成(第一条微指令地址)
3. 微PC自动增量
4. 根据各种标志确定微指令分支转移的地址
5. 由硬件直接产生，即通电后，第一条微指令地址

### 微指令格式

和微指令编码方式有关，分为：
1. 水平型：上面三种都属于水平型，一个微指令定义多个微命令，这些微命令并行执行，优点是微程序短，并行能力强；
2. 垂直性：一种微指令只能对应一种微命令，指令短，简单规整，但是微程序长，执行速度慢

**注意**：
1. 水平型微指令采用操作控制，但是垂直性微指令采用微操作码

# 异常和中断机制

CPU内部的意外事件为**异常/内中断**,CPU外部设备发送的中断请求为中断；异常是CPU执行指令时检测到的和指令有关的同步事件，而外中断是和指令无关的异步事件；

**处理过程**：若在指令执行过程中发现异常/指令执行结束后发现中断，那么打断程序进入中断服务例程；随后若成功解决问题，则执行中断/异常返回指令回到原来程序继续执行

## 分类

**异常**：
1. 硬故障中断：硬连线出现异常，例如存储器错误等
2. 程序性异常/软件中断：执行指令引发的异常事件

按照发生原因分为：
1. **故障(程序性异常)**：指令执行过程中发现的异常事件；
2. **自陷(程序性异常)**: 预先安排的异常事件，在执行到陷阱指令后，转到对应的中断服务例程执行，随后返回并执行陷阱指令的下一条，用来实现系统调用
3. **终止(硬故障中断)**：CPU内部硬件故障，例如控制器出错，总线错误

**中断**: 外部IO设备通过特定的中断请求信号线向CPU提出中断请求；分为：
1. 可屏蔽：CPU可以设置中断屏蔽字来屏蔽这种中断
2. 不可屏蔽中断

**注意**：
1. CPU检测外部中断，需要根据中断请求线确定中断源，随后才能根据中断源设置中断屏蔽字/中断服务例程

## 异常和中断响应过程

**响应**包括检测到异常/中断，关中断，保存断点，识别异常异常/中断并转到服务例程(保存断点指PC和PSW，具体现场由中断服务例程保存)

**异常/中断识别方式**：
1. 异常一般使用软件识别：通过异常状态寄存器保存异常信息，随后操作系统用一个程序按照优先级查询该寄存器，来检测异常类型，随后转到特定处理程序
2. 中断识别方式可以使用软件识别，也可以使用**硬件识别/向量中断**：每个中断都有一个中断类型号，根据该号(作为地址)去中断向量表中找到对应的中断向量，中断向量即特定中断服务例程程序的首地址；

**注意**：响应过程因为关中断，因此不可以被打断

# 指令流水线

**并行技术**：
1. 时间上：例如指令流水线，同一时间有多条指令在一个部件上执行
2. 空间上：设置多个执行相同任务的功能部件；

指令执行过程可以分为多个阶段/流水段，每个阶段由一个功能部件完成，分为：
1. 取指IF
2. 译码并取数ID
3. 执行，计算EX
4. 访存MEM
5. 写回，将结果写回寄存器中WB

如果指令按照上面的五段来分，每个时钟周期都有一条新指令进入流水线，并且假设流水线不阻塞，那么执行n条指令需要n+5-1个时钟周期，CPI为1；

为了实现流水线，指令应该具备如下性质：
1. 长度一致，简化取指和译码，避免增长流水段时间
2. 指令格式规整，有利于在译码前知道寄存器位置
3. 只能用load/store指令访存
4. 数据和指令按边界对齐，减少访存次数

## 基本实现

### 设计原则

1. 流水段个数以最复杂指令的个数为准
2. 流水段长度以最长流水段为准
3. 不能缩短单条指令时间，但是加快了很多整个程序的执行速度

### 流水线逻辑结构

每个流水段后面都有一个流水段寄存器，存储本段处理的所有数据；一般不考虑流水段寄存器的延迟；

## 流水线冒险

**冒险**为一些情况使得后续指令无法执行引起流水线阻塞，共有三种冒险，先给出不同指令在不同流水段要干的事：

| Instruction | IF | ID | EX | MEM | WB |
| ---- | ---- | ---- | ---- | ---- | ---- | 
| 计算 | 取指  | 译码并取数 | 计算 | None | 结果写回寄存器 | 
| load/store | 取指 | 译码并取数 | 计算访存地址 | 访存 | 将数据写回寄存器 |
| 跳转 | 取指 | 译码并取数 | 计算目的地址，设置条件码 | 若条件成立，将转移地址送PC | None |

### 结构冒险

不同指令在同一时刻争用同一功能部件而形成的冲突，例如一条指令IF和另外一条指令的MEM都要使用主存，造成冲突；解决方法如下：
1. 当访存部件工作时，即有指令在MEM访存时，延迟一条指令，也就是这个时钟周期不读入新的指令
2. 设立多个独立部件，例如寄存器设立读/写口，主存中将指令和数据分开存储

### 数据冒险

后面用到的数据还没有产生，称为RAW冲突；有如下方法解决冲突：
1. 延迟相关指令;注意此时如果寄存器读写口分离，那么WB和ID可以在同一时钟周期执行，前半个周期WB写，后半个周期ID读
    - 插入nop指令
    - 硬件阻塞
2. 转发旁路技术：即将数据通路的中间数据(存储在流水段寄存器中)直接输入ALU；采用可以解决除了load-use之外的任何数据冲突

**load-use**数据冲突：后面一条指令需要用到前面一条load指令加载的数据；ID阶段要用到的数，在前一个指令的MEM结束后才能取到；解决方法是：如果有旁路技术，那么需要插入一个nop，否则需要插入两个nop，让ID和WB重叠；或者编译器优化，避免出现该数据冒险

### 控制冒险

指令改变指令执行顺序，造成断流，即控制冒险；最简单的解决方法就是延迟转移指令后续指令的运行；延迟的时钟周期数称为**延迟损失时间片C**，对于一条转移指令，在MEM阶段才能将转移地址送到PC，因此后一条指令的IF需要延迟到转移指令的WB才行，C为3；还有如下方法解决：
1. 进行分支预测：尽早生成转移目标地址；分为：
    - 静态预测：
    - 动态预测：

## 性能指标

1. **吞吐率**：单位时间内流水线完成的任务数量
2. **加速比**：完成一批任务，使用流水线和不使用的时间比值；

## 高级流水线技术

1. **超标量流水线/动态多发射**：配置多个功能部件，每个时钟周期加载多条指令,CPI<1
2. **超长指令字技术**：静态多发射，编译器将可以并行的指令组合成一条具有超长OP码的指令
3. **超流水线技术**：将流水段划分增多，提高流水线主频来提升吞吐率；但是流水段增多，单个流水段时间越短，用于流水段寄存器的时间就越长，因此不能无限增加流水段个数

**注意**：
1. 指令译码得到的控制信号需要通过流水段寄存器传递到下一个流水段
2. 前面的分支指令和后面的计算指令可能发生数据冒险，因为有的分支指令是在某个情况下设定某个变量的值
3. 超长指令字对译码硬件有更高要求
4. 超标量流水线可以结合动态流水线调度技术，通过动态分支预测，使得指令不按原本顺序运行

# 多处理器的基本概念

1. 单指令流单数据流SISD：一段时间仅执行一条指令，可以使用流水线提高并行度，并控制一个数据流
2. SIMD：一个指令同时控制多个数据流；有多条数据流，虽然执行同一条指令，但是有各自的存储元件，存储不同数据，相当于多个数据通路对不同的数据同时做相同操作；
3. MISD：不存在
4. MIMD：多个指令同时运行，控制多个数据通路，分为
    - 多计算机系统：有多个计算机节点和私有的主存；
    - 多处理器：多个处理器共享单一存储器

SIMD处理数组很方便，例如对数组中所有元素做相同操作，那么可以一次性将数组所有元素都取出来，然后放到不同的数据通路中做相同操作(向量处理器)

## 硬件多线程的基本概念

线程切换成本很高，因此有了硬件多线程，此时硬件为多个线程分配单独的PC和寄存器，线程切换只需要选中不同的PC和寄存器即可，分为：
1. 细粒度多线程：多线程轮流执行，线程之间不相关，可以乱序并行执行，每个时钟周期都切换线程
2. 粗粒度多线程：不是每个时钟周期都切换，而是在某线程被阻塞时，例如cache缺失，就切换到别的线程；线程切换的成本比细粒度更大；这两种只实现了指令的并行
3. 同时多线程SMT：真正实现了线程的并行，在同一时钟周期发射多个不同线程的指令；

## 多核处理器的基本概念

多个处理单元/核集成到单个CPU，每个核可以共享/独享Cache，但是一般共享主存

要发挥多核处理器的能力，需要使用多线程，此时多线程真正实现了并行，即同一时刻有多个线程执行

## 共享内存多处理器(SMP)的基本概念

具有共享的单一物理地址空间的多处理器，所有核都可以访问存储器的任何位置，有如下两种：
1. 同一存储访问UMA：每个处理器对存储的访问时间基本一致
2. 非统一存储访问NUMA：主存被分割给不同的处理器，处理器访问属于自己的主存速度很快；

早期，内存控制器不在CPU中，而是在内存中，因此不同处理器访问主存都要争用同一个控制器，这是UMA架构，资源冲突限制了访存性能；NUMA诞生，内存控制器并集成到CPU中并且每个处理器都有各自的内存控制器；处理器直连接到一部分内存(本地内存)，处理器之间通过线连接，处理器可以通过线访问别的处理器的本地内存；

因为上面两种架构，都是每个处理器都有独享的Cache，因此多核处理器的cache一致性包含cache和主存/cache之间的一致性；
