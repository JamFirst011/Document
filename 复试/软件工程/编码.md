# 编码(主要有哪些规范，如何达成这些规范，如何开发单元测试样例，以及度量代码复杂度)

## 编码规范

**设计易读的代码**: 
- 布局格式规范: 例如使用缩进表示逻辑结构，使用空行分隔逻辑等
- 命名规范: 使用有意义的名称进行命名
- 注释规范:

**设计易维护的代码**: 
- 小型任务: 将软件分为小的任务，提高其内聚性，并以此提高可维护性
- 进行封装: 用有意义的名称封装复杂决策，即将一个复杂bool表达式写到一个新函数中
- 使用表驱动编程: 如果需要做一系列决策(if)，那么可以将决策需要的数据放在数组/表中，并边遍历边进行决策
- 数据使用: 一个变量用于一个目的，不用全局变量，明确模块间模糊的依赖关系(写注释);

**设计可靠代码**: 
- 契约式设计: 如果一个函数在满足前置条件的情况下开始执行，在满足后置条件的情况下结束，那么就是可靠的, 契约式设计有两种常见的编程方式，`异常和断言`
- 异常方式: 开始时检查前置，不满足就抛出异常，结束时做同样处理
- 断言方式: 用 assert 来检查前置和后置
- 防御式编程: 核心思想为在函数和外界交互时，在外界条件发生错误时，保证内部不受损害; 即检查所有的输入和前置条件，比如输入参数，调用别的函数的返回值, 但不检验后置条件和输出(同样使用异常和断言实现)

4. 使用模型辅助设计复杂代码: 决策表，伪代码，流程图。

## 复杂度度量

**代码复杂度度量**: 
- 圈复杂度: 为代码建立程序流程图，该代码的复杂度为边数-节点数+2; 
- 直接计算程序中决策点的数量作为复杂度: 即 if，for 等决策点
- 类中所有方法的代码复杂度的和
